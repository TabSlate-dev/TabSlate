# Export, Restore, and More Import Sources (Sub-project F)

## Summary

TabSlate imports Chrome bookmarks and Toby exports, and it cannot export anything. Users cannot take their library elsewhere, back it up, or move it between accounts, and with web snapshots (C2) becoming paid, that matters more.

This sub-project adds three exports: a complete JSON export that TabSlate can restore, a browser bookmarks HTML export that browsers and other tools can import, and a server-side zip of all snapshot files. It also adds imports from other browsers, Pocket, Raindrop, Karakeep, Linkwarden, and the tab managers TabSlate users are most likely to come from: OneTab, Session Buddy, Tab Session Manager, and Workona.

## Roadmap Context

The faved.to comparison (see `docs/superpowers/specs/2026-10-15-library-management-basics-design.md`) produced sub-projects A to E. A review of the plans against that comparison and against Karakeep added three more:

| Sub-project | Scope | Repositories |
|---|---|---|
| A — Library management basics | View preferences, tag and collection editing, counts, tag search, clickable tags, save shortcut, duplicate detection | Frontend |
| B — Bulk operations and unified form | Multi-select and bulk bar, unified add/edit form, notes, edit time, more sort options | Frontend + server |
| C1 — Image card view | Small and large card views, `og:image` covers, "Fetch details" in the form | Frontend + server (one field) |
| C2 — Web snapshots | Server and browser page capture, snapshot viewer, full-page archives, possibly broken links, storage quota | Server + cloud + frontend |
| D — Nested tags and import hierarchy | Tag hierarchy, tag tree, folder hierarchy on import, merging and cleaning up tags | Frontend + server |
| E — Onboarding | First-run checklist | Frontend |
| **F — Export, restore, and imports** (this spec) | JSON and HTML export, restore, snapshot zip, nine new import sources | Frontend + server |
| G — Search syntax and smart collections | Query qualifiers, saved searches | Frontend (+ server search) |
| H — Local AI tagging and summaries | AI features using the user's own endpoint and key, stored only on the device | Frontend |

**Depends on B, C1, D, and C2.** Exports and restores carry B's notes and edit times and C1's covers. Imports use D's import root tag, folder hierarchy, and tag paths. The snapshot zip needs C2; the rest of F does not.

## Goals

- Export the whole library in a format TabSlate can restore, and in the browser bookmarks format other tools understand.
- Restore a TabSlate export into the same or another account.
- Let users take all their snapshot files with them.
- Import from the bookmark tools and tab managers that TabSlate users most likely used before.
- Keep every import local: files are parsed in the extension and never uploaded.

## Non-goals

- CSV export.
- Automatic backups, on the device or on the server.
- Restoring trashed items.
- Importing text-only bookmarks (Karakeep) or Pocket highlights.
- Choosing individual bookmarks to import, beyond choosing sessions for tab managers.
- Importing through other services' APIs; imports read export files only.
- Two-way sync with browser bookmarks.

## Decisions

| Question | Decision |
|---|---|
| Exports | Complete JSON (restorable) and browser bookmarks HTML, both generated in the extension; a snapshot zip generated by the server. |
| Backups | No automatic backups. Signed-in users' data already lives on the server; the trash and the JSON export cover mistakes. |
| Restore | A new import source. IDs are always regenerated; each exported workspace restores to a new workspace or merges into an existing one. |
| New import sources | Other browsers' HTML, Pocket, Raindrop, Karakeep, Linkwarden, OneTab, Session Buddy, Tab Session Manager, Workona. |
| Tab managers | Each session, group, or Workona workspace becomes a collection. The user picks which sessions to import. |
| Source tags | Tags from the source merge into same-named top-level tags; folder and list hierarchy goes under D's import root tag. |

## Design

### 1. The Data tab

The settings dialog (`components/dashboard/settings-dialog.tsx`) gains a **Data** tab next to General, Plan, and Account. It holds:

- **Import** — the import section moves here from General. `tabslate-open-import` and its existing entry points still open the import dialog.
- **Export** — the two exports in sections 2 and 3, with a scope choice: all workspaces or the current workspace.

The snapshot zip (section 5) lives in C2's Web snapshots settings section, because only users with snapshots need it.

### 2. Complete export (JSON)

- The extension reads everything from IndexedDB, including archived and trashed bookmarks, which it reads directly without loading them into the stores. It builds the file in memory and downloads it through a `Blob` URL, so no permission is needed. Guests can export too.
- The file name is `tabslate-export-YYYY-MM-DD.json`.
- Format:

  ```json
  {
    "format": "tabslate-export",
    "version": 1,
    "exportedAt": "2026-10-21T08:00:00.000Z",
    "extensionVersion": "0.x.y",
    "workspaces": [{ "id": "…", "name": "…", "color": "…", "position": 0 }],
    "collections": [{ "id": "…", "workspaceId": "…", "name": "…", "icon": "…", "position": 0, "isDefault": false, "state": "active" }],
    "tags": [{ "id": "…", "name": "…", "color": "…", "parentId": "…" }],
    "bookmarks": [{
      "id": "…", "collectionId": "…", "title": "…", "url": "…", "description": "…",
      "notes": "…", "imageUrl": "…", "favicon": "…", "tags": ["…"], "isFavorite": false,
      "state": "active", "createdAt": "…", "updatedAt": 0
    }],
    "groups": [{ "id": "…", "workspaceId": "…", "name": "…", "color": "…", "isCompact": false,
                 "tabs": [{ "title": "…", "url": "…", "favicon": "…", "position": 0 }] }]
  }
  ```

  - `state` is `active`, `archived`, or `trashed` for bookmarks and collections.
  - Only active workspaces are exported. Content held by a deleted, recoverable workspace stays in the workspace manager.
  - Sync bookkeeping (`seq`, tombstones) is not exported.
- **Never exported:** sign-in data and tokens, H's AI settings and key, device preferences, onboarding state, and snapshot files (section 5 covers those).

### 3. Browser bookmarks export (HTML)

- The standard Netscape bookmark format, which Chrome, Firefox, Safari, Edge, and most bookmark tools import. The file name is `tabslate-bookmarks-YYYY-MM-DD.html`.
- Structure:
  - With "all workspaces", each workspace is a folder; with "current workspace", its collections sit at the top level.
  - Each collection is a folder, ordered as in the sidebar. Bookmarks without a collection go into an "Uncategorized" folder.
  - Optional: "Include archived bookmarks" adds an "Archive" folder per workspace. Trashed bookmarks are never included.
- Each bookmark is `<DT><A HREF="…" ADD_DATE="…" LAST_MODIFIED="…" TAGS="…">title</A>`, followed by `<DD>` with the description and the notes separated by a blank line.
- `TAGS` lists full tag paths joined with `/`, separated by commas. Commas inside tag names become spaces.
- Favorites, covers, and saved groups have no standard representation and are left out.
- Everything is HTML-escaped.

### 4. Restoring a TabSlate export

The import dialog gains the source **TabSlate backup (JSON)**.

- The file must have `"format": "tabslate-export"` and a supported `version`.
- The preview lists each exported workspace with its collection and bookmark counts. For each one, the user chooses to restore it as a new workspace (the default while the workspace quota allows) or to merge it into an existing workspace, or to skip it.
- Restoring:
  - All IDs are regenerated, so restoring into the original account, another account, or another server never collides with existing records.
  - Collections are recreated, with "(2)" on duplicate names when merging into an existing workspace. Archived collections and bookmarks restore as archived.
  - Bookmarks keep every exported field: title, URL, description, notes, cover, favicon, favorite, creation and edit times.
  - Tags merge into existing tags by full path; missing levels are created (D).
  - Saved groups restore into the chosen workspace.
  - Trashed items are not restored.
  - Bookmarks that duplicate existing ones are skipped, as in every import.
- Quotas behave as in other imports: collection, bookmark, and workspace quotas block the restore; tags that do not fit fall back as in D.
- JSON files may be up to 50 MB; other import files keep the 20 MB limit.

### 5. Snapshot zip export (server)

- Settings → Web snapshots gains "Export all snapshots", shown when the user has snapshots.
- `POST /snapshots/exports` starts an export job (`409` when one is already running, `429` when the last one started less than 24 hours ago). `GET /snapshots/exports/latest` returns its status and, when ready, a download URL.
- The worker streams the zip into storage at `exports/<userId>/<exportId>.zip`, so memory use does not grow with the archive:

  ```
  index.html                      – every bookmark, grouped by workspace and collection, linking to its folder
  <collection>/<title>-<id>/
    metadata.json                 – URL, title, capture time, source
    reader.html
    screenshot.jpg
    archive.html                  – when a full-page archive exists
    file.pdf | file.<ext>         – for image and PDF snapshots
  ```

- The download URL is signed and expires after 7 days, when the file is deleted. Export files do not count against the storage quota.
- While the settings section is open, the extension checks the status every 10 seconds; otherwise the result is waiting the next time the user opens it. The sync stream only carries sequence numbers, so it is not used for this.

### 6. Import sources

**Rules for every source.**

- Files are read and parsed in the extension; nothing is uploaded.
- Bookmarks go into the chosen target workspace. Duplicate collection names get "(2)", and bookmarks that duplicate existing ones are skipped.
- The preview summarizes the collections, tags, and bookmarks to be created. Collection and bookmark quotas block the import.
- D's "Record the import source and folder hierarchy as tags" option applies to every source. The root tag "«Source» import «YYYY-MM-DD»" goes on every imported bookmark, and a source's folder or list hierarchy is built under it with D's rules.
- Tags that come from the source (Pocket, Raindrop, Karakeep, Linkwarden, and Toby labels) are the user's own taxonomy, so they merge into same-named top-level tags instead of going under the root tag.
- After importing, D's "Show imported bookmarks" applies.
- The source list is grouped: Browsers, Bookmark tools, Tab managers, and TabSlate backup.

**Mappings.**

| Source | Collections | Hierarchy and tags | Other fields |
|---|---|---|---|
| Browser bookmarks HTML (Chrome, Firefox, Edge, Safari) | Each first-level folder, as in D. Bookmarks at the very top of the file go into a collection named after the browser. | Deeper folders go into the tag tree. Tags in `TAGS` attributes are imported. | Root folders are recognized by structure (top-level folders, `PERSONAL_TOOLBAR_FOLDER`), not by their localized names. Mobile bookmark folders are skipped, as today. |
| Pocket (CSV: `title, url, time_added, tags, status`) | One "Pocket" collection | `tags` (separated by `\|`) merge by name | `time_added` is the creation time; `status = archive` imports as archived. |
| Raindrop (CSV: `id, title, note, excerpt, url, folder, tags, created, cover, highlights`, and `favorite` when present) | Each first-level `folder`; bookmarks without one go into "Raindrop" | Deeper folder paths go into the tag tree; `tags` merge by name | `note` → notes, `excerpt` → description, `cover` → cover (C1), `created` → creation time, `favorite` → favorite. |
| Karakeep (JSON) | Each top-level manual list; bookmarks in no list go into "Karakeep" | Nested lists go into the tag tree. A bookmark in several lists goes into its first list's collection and gets the others as tags. | `note` → notes, `archived` → archived. Text bookmarks are skipped and counted in the summary. Smart lists import as G's smart collections once G exists; until then they are skipped. |
| Linkwarden (JSON) | Each top-level collection | Nested collections (`parentId`) go into the tag tree; tags merge by name | `name` → title, `createdAt` → creation time, and a description when the export has one. |
| OneTab (text: `url \| title` lines, blank lines between groups) | Each group, named "OneTab 1", "OneTab 2", … in file order | — | — |
| Session Buddy (JSON: `collections` → `folders` → `links`) | Each collection, named by its `title` | Windows are merged in order | A link's `title` (the user's edited title) wins over `titleOriginal`. |
| Tab Session Manager (JSON: sessions → windows → tabs) | Each session, named by its name or, without one, its save time | Windows are merged in order | — |
| Workona | Each workspace | Sections go into the tag tree | The exact format is confirmed from a real export during planning. |

**Choosing sessions.** For OneTab, Session Buddy, Tab Session Manager, and Workona, the preview lists the sessions, groups, or workspaces with their tab counts, with select-all and select-none. Tab Session Manager preselects named sessions and the most recent session, because its automatic saves can number in the hundreds; the other sources preselect everything.

**Parsers.** Each source has its own module under `lib/import-*.ts`, returning the common `ImportPlan` (with D's tag parents). The CSV sources use one small CSV reader that handles quoted fields and line breaks inside them. Unknown columns are ignored, and a file missing a required column is rejected with a message naming the column.

## Error Handling

- Exports read IndexedDB in one pass; a read failure shows an error and produces no file.
- Imports reject unrecognized files with a message that names the expected source, and malformed rows are skipped and counted in the summary.
- A restore whose `version` is newer than the extension supports asks the user to update the extension.
- Snapshot exports that fail show the reason with a retry, which does not count toward the 24-hour limit. Expired download links show "This export has expired".

## Testing

Each behavior is implemented test-first.

- **Unit tests:**
  - every parser against its fixtures, including empty and malformed files, quoted CSV fields with line breaks, and Chrome, Firefox, Edge, and Safari HTML exports;
  - the mappings: collections, hierarchy under the root tag, source tags merging by name, archived states, notes, covers, favorites, and skipped text bookmarks;
  - session preselection;
  - exporting JSON and restoring it reproduces the library, apart from regenerated IDs and trashed items;
  - the HTML export's structure, escaping, and `TAGS` paths.
- **Server tests:** the zip layout, one running export per user, the 24-hour limit, signed URL expiry, and file deletion.
- **Component tests:** the Data tab, the grouped source list, session selection, and the restore's workspace choices.
- **Manual check:** import the HTML export into Chrome and Firefox; restore a JSON export into a second account; import a real export from each source. Fixtures are anonymized real exports; the Workona fixture needs an export from the user.

## Accessibility and Internationalization

- Exports and imports report progress and results through `role="status"`.
- The session list is a labeled list of checkboxes with select-all and select-none buttons.
- Every new string is translated in English and Simplified Chinese with `[component]_[description]` keys, including the root tag names for each source.

## Resolved During Design

- **No automatic backups.** Signed-in users' data is already on the server, the trash protects against deletions, and the JSON export gives users their own copy. Local scheduled backups would need the downloads permission.
- **New IDs on restore.** Keeping IDs would collide with existing records when restoring into another account on the same server and would make merges ambiguous.
- **Tab managers into collections.** Collections can be tagged, searched, and acted on in bulk, and B's "Open as a tab group" restores a session in one click. Saved groups would lose all of that.
